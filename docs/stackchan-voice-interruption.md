# 语音插话：使用方式与实测限制

[返回中文首页](../README.md)。本页描述 `master` 中尚未发布的插话源码；已有 `0.1.0-alpha.2` Release 安装包不包含此功能，不要仅依据固件显示的版本号判断是否支持。

## 怎样使用

标准 K151 构建默认启用设备端 AEC（回声消除）和 `realtime` 模式。唤醒进入对话后，机器人讲话时可以直接说下一句话，无需再次喊唤醒词。

先说“把音量调到百分之六十”，再说“讲一个长一点的故事”，播放中直接说“重新给我讲一个笑话”。`self.audio_speaker.set_volume` 是原有音量工具；60% 指工具的 0～100 设置值，不是声压或线性功率百分比。请先确认音量设置成功。

代码没有把默认音量改为 60%、没有强制限制最大音量，也不会覆盖 NVS 中的已有音量。

## 单台实测结果（2026-10-07）

硬件为 StackChan K151 / CoreS3，使用原有麦克风、扬声器与底座，连接小智官方云端；采集增益为 30 dB，AEC 使用 FD_LOW_COST / VERYAGGR。本轮通过现有音量工具改变播放音量，未同时改变增益、AEC 或打断判定。

| 播放音量 | 用户现场反馈 |
| --- | --- |
| 60% | 可以正常打断并使用，相比此前明显改善 |
| 80% | 需要喊得明显更大声才能打断，普通说话不够可靠 |

这是单台用户实测，未严格控制距离、背景噪声和播放内容，没有统计识别率；不能保证所有 K151 在 60% 都有同样效果。音量升高后识别变差的具体原因尚未分离验证，不能断言只是 AEC 强度造成。

在 60% 音量的测试中，用户报告没有再次自行打断；这不等于已验证所有场景均不会误触发。仍出现以下识别错误：

| 用户说的话 | 云端返回的 STT |
| --- | --- |
| 重新给我讲一个笑话 | 重给给我讲一个笑话。 |
| 停 | 嗯。 |
| 我不想停了 | 我不想听了。 |

长句后半段可能识别正确，开头和单字短词仍可能错误。能停止当前播放不代表识别文字正确，也不保证模型会执行“停”的意图。插话响应延迟未作定量测量。

## 当前处理流程

1. ES7210 采集麦克风与扬声器的电气回声参考信号。
2. 设备 AFE/AEC 处理后持续上传音频，包括机器人讲话期间。
3. 云端处理插话与语音识别，下发 TTS/STT 等消息。

本地 WebRTC VAD 报告语音状态，但没有新增“VAD 一触发就自动停播”的策略。可确认打断由云端触发，官方云端内部采用哪种 VAD 或识别算法未公开核实。

**尚未实现：丢弃停播前音频，只识别停播后的剩余内容。** 持续上传的数据不能通过清空设备队列撤回。公开 [WebSocket 协议](https://github.com/78/xiaozhi-esp32/blob/main/docs/websocket.md)及 [MQTT/UDP 协议](https://github.com/78/xiaozhi-esp32/blob/main/docs/mqtt-udp.md)没有明确规定清除当前 ASR 缓存与确认新轮次的命令。`tts.stop` 同样用于正常播放结束，不能将每个 stop 当成独立的插话确认。是否存在未公开的云端能力仍需确认。

## 已知稳定性问题

- **自动重启尚未修复。** 本轮匹配固件符号的调用栈为：`Application::Run → LvglDisplay::UpdateStatusBar → StackchanK151Board::GetBatteryLevel → Axp2101::IsCharging → GetBatteryCurrentDirection → I2cDevice::ReadReg`。读取电池状态时发生 `ESP_ERR_TIMEOUT`，`ESP_ERROR_CHECK` 调用 `abort()` 后软件重启。FT6336 的可恢复读取不覆盖这条电池读取路径，I²C 超时的底层原因尚未确认。
- **CPU 调度问题尚未修复。** 播放/实时收音期间出现 CPU 0 的 IDLE0 看门狗告警，运行任务为 `audio_input`，调用栈位于 AEC NLP / `aec_process` / AFE feed。告警后程序仍运行，后续因上述电池读取错误重启；不能将二者简单认定为同一原因。
- 有编码队列满后丢弃旧帧的记录；日志显示播放期间麦克风样本达到 int16 边界。满幅统计是失真线索，不能单独证明模拟 ADC 削波或判定根因。

因此这一版仅适合实验测试，不作为长期稳定运行的保证。本次提交不修改电池读取处理、不关闭看门狗，也不增加新的自动停播逻辑。

## 验证与反馈

已做单台收音、播放、唤醒、连续直接插话及安静时是否误打断的观察。全部交互组合、长时间运行、断网重连和其他硬件仍需验收。主机测试与编译只验证软件，不替代实机验收。

排查时保持距离、说话音量和测试短句一致，先只改变播放音量。开发版每秒输出 `RawDuplex`（原始 MR 输入统计）、`DuplexInput`（重采样后统计）和 `RealtimeCapture`（AFE 输出统计），不保存录音。相关性仅比较少数候选延迟，不是完整回声消除质量评分。

反馈请说明播放音量、实际说的话、返回的 STT、是否在讲话期间插话、是否自行打断、是否重启。请勿公开整机备份、NVS、原始联网日志、账号或 Token。

如需回到等待说完再收音，在[标准构建命令](stackchan-development.md#获取源码与构建)后追加：

```sh
--build-options-json '{"aec_mode":"off"}'
```

该选项关闭设备端 AEC 与参考输入，回到非实时聆听方式；不会自动改写个人绑定和头部校准。
