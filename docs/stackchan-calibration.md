# 每台 StackChan 的本地校准

[返回首页](../README.md) · [板卡说明](../main/boards/m5stack/stackchan-k151/README.md)

适用于 0.1.0-alpha.1 及之后源码。本版不再在源码中写死单台设备 MAC 和舵机零点。**零点必须来自这台机器自身的原厂配置或可靠的校准记录，不能照抄历史里的数值。** 编译成功不能证明机械方向与限位正确。

## 配置从哪里来

优先从本台原厂配置、已保存的原厂配置记录或备份中只读提取 yaw/pitch zero。原厂备份可能含网络或账号信息，只在本机处理，不上传仓库。安装包的只读备份工具已支持提取原厂 `servo/zero_pos_1` / `zero_pos_2` 和本项目版本化校准记录，见[安装指南](stackchan-install.md)。它不自动标定，也不会授予验收资格；如果没有可靠零点，先保持头部禁用，按原厂方法确认配置再继续。

不要直接把当前舵机 raw 值当作零点：头可能处于抬头或偏转状态，原厂 pitch 坐标也不是水平为 0°。本次改动不写舵机 EEPROM，不改变舵机永久零点、模式或限位。

## 首次使用

先确认显示屏与本项目配置兼容、机器人放稳、头周围无遮挡，线缆接底座且不妨碍转动。下述流程是在已部署并核对应用、资源和分区兼容性的前提下，通过本地 USB 串口控制台执行；不是一条通用刷机步骤。本次维护未自动执行这些命令。

1. 启动时缺少有效配置会提示 `No per-device calibration`，不初始化舵机运动、摸头动作或 RGB 工作任务。屏幕与对话仍按自身初始化结果工作。`head status` 的 `calibrated=false`，AI 动作请求会拒绝；禁止通过 AI 跳过验收。
2. 输入 `head calibrate <yaw_zero> <pitch_zero>`，将占位符换成**本台**原厂零点整数。保存后 `calibration_restart_required=true`，此会话禁止继续启用动作；短按 RST 后重新连接控制台。
3. 输入 `head calibration` 和 `head status`，核对已载入的零点、`calibrated=true`、`approved=false`。有效配置启动后读取反馈和存储限位，但不会自动回正或使能扭矩。输入 `head diag` 查询诊断寄存器。诊断版本同时报告当轮有效反馈中的 `raw`、`speed_word`、`load_raw`、`current_raw`、`voltage_raw`、`temperature_raw` 和 `moving`；读取失败报告 `feedback unavailable`，不使用旧值。字段为原始寄存器值，不能在未核对本机型号与单位时直接当作安培、伏特或物理转速。此诊断不写舵机 EEPROM，也不增加周期性查询。
4. 等待 `feedback_valid=true`，确认没有故障，实际姿态与坐标解释吻合。不能在反馈无效、越界、过载或通信异常时继续。
5. 本地输入 `head arm` 临时启用，再分别输入 `head probe yaw`、`head probe pitch`。每次只增量 2°，观察实际方向、动作与反馈，等停止后再做下一次。`head stop` 可停止。探测触及边界时可能拒绝，需要先按原厂方法核对姿态，不能反复强推。
6. 两轴小幅探测、回正、机械方向与所需范围都由你确认安全后，在静止状态输入 `head approve`。这是人工验收声明，代码并不自动证明机械范围安全，也不强制记录你是否完成两轴探测。保存成功后启用自动动作；保存失败保持禁用。
7. 查询状态核对 `approved=true`、反馈有效，无故障后再逐步测试点头、摸头和跳舞，按[实机验收清单](stackchan-hardware-validation.md)记录结果。

头部范围仍为 yaw −30～30°、pitch 5～60°，回正目标 (0,10)。配置验证还要求整个命令范围能映射到 0～1023 的编码器：yaw zero 96～927、pitch zero 0～831。这只是数字边界检查，不是对其他机械结构的安全保证。

### 如何判断探测结果

反馈分别报告动画是否仍在进行、舵机运动标志和实际角度。`state=stopped` 表示动画（包括最后一次目标写入）与舵机均停止，不承诺角度精确等于目标。`yaw_error`、`pitch_error` 是目标减实际的残余偏差；小偏差本身不是故障，也不能自动连发重试。旧诊断版的 `completed` / `target_not_reached` 不再用作停止状态。

`local_verification_required=true` 表示本机验收尚未批准；`remote_motion_block_reason` 仅区分 `local_verification_required`、`motion_not_armed` 与 `none`，还必须核对校准/重启要求、有效反馈、通信恢复与故障状态。未验收不是电机故障，不能由 AI 自行批准。

`motion_no_progress` 是较大目标误差下 1.2 秒没有位置进展时的保守停止，不能描述为机械卡住。`mechanical_stall` 还要求原厂规则中的位置无进展与电流/负载证据（50 ms 采样、确认两次，进展或方向变化时重置）；过载、无效反馈、通信超时仍分别保护。该分类不解除任何停止保护。

对最近一次明确的姿态命令（回正、指定姿态或两轴探测），另报告：

- `pose_command_tracking`：是否有该类命令的结果记录；停止、其它新命令会清除记录。
- `pose_command_finished`：该次动画与舵机运动已结束，不等于成功到位。
- `pose_command_motion_observed`：有效反馈中是否观察到至少一个编码器步长的实际变化。
- `pose_command_target_reached`：该命令结束后的严格编码器对齐诊断（误差不超过一个编码器步长，约 0.3125°）；不代表原厂承诺的机械精度，不作为动作完成或批准验收的唯一条件。

这些结果不代表整段跳舞、点头、摸头或其它自动动作已完成。原地姿态命令可能已到位但没有发生运动；探测时必须同时核对目标、角度变化、现场方向和动作是否顺畅。修正版未实机验收前，不能凭主机测试宣称头部正常。

## 修改校准与升级

已验收或已临时启用时，不允许直接替换零点：

```text
head revoke
# 等待停止，短按 RST，重连控制台
head calibrate <本台新的yaw_zero> <本台新的pitch_zero>
# 短按 RST，重连；重新读反馈和完成本地验收
```

撤销或保存新配置后必须先重启，不能继续写第二份配置。状态中的零点显示本次启动已载入值，重启前不会变为尚未载入的新值。撤销会暂停动作并尝试释放扭矩；通信异常时不能保证硬件收到释放命令，需查询状态并检查连接。

旧版使用的 `head_ctl/verified` 保留但不再读取；新版不会从旧值推断已经安全，也不会自动沿用历史单台零点。升级后须配置本台零点并重新验收。不要清空整个 NVS，绑定信息与其他设置不需要重置。

新记录为 `head_cal/config` 的单一版本化 NVS blob（schema 1，零点与 verified）；保存新配置同时清除验收标志。未知 schema、错误长度或越界记录均失效。它存储在设备自己的 Flash；**不要把包含已验收配置的 NVS 镜像复制到另一台机器**，当前没有对克隆配置做设备身份绑定。应用源码和 CI 工件不包含这份配置。
