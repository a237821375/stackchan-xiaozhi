# StackChan K151 测试烧录包实施计划

用户已确认：准备免编译安装包，在本台 K151 验证最终流程后发布限定硬件的测试 Release。继续本会话执行，不改用户既有 Git 配置。

## 范围与约束

只支持已验证的 K151 / ESP32-S3 / 16MB / Quad PSRAM / ILI9342C 配置；不宣称其他屏幕版可用。发布独立测试版本 0.1.0-alpha.2，保留运动保护和人工本地验收。不得发布本机 Flash/NVS/账号/联网日志。资源分开打包，不能把默认表情的合并镜像当成成品。

## 任务1：每台备份的只读校准读取

新增 tools/stackchan_backup.py 与 tests/test_stackchan_backup.py：partitions_from_flash(bytes) 读取/验证分区表；calibration_from_flash(bytes) 只返回原厂 servo 零点或本项目校准，并清除 approval。独立构造 CRC/NVS/分区测试，先红后绿；原厂历史备份只在本机只读核对，不上传。

## 任务2：安装包及失败前置检查

新增 tools/build_stackchan_release.py、tools/stackchan_install.py、tests/test_stackchan_release.py、tests/test_stackchan_install.py：构建 manifest/校验/分区文件清单，校验16MB板卡配置、正确app版本和自定义41状态资源。安装器无SDK依赖，只需Python与固定esptool/pyserial；写入前验证整机备份完整、设备身份相同、镜像hash/地址/区域正确，并生成明确计划。

首次安装和升级分开；兼容升级只更新当前启动app与自定义assets，不覆盖bootloader/partition/otadata/NVS。首次切换使用独立boot/partition/otadata/app/assets文件，必须保持本台NVS映射与校准可追溯，布局不兼容时拒绝并给出处理方案，不能默默擦除。无erase_flash、无用户设备配置进入发布包。失败测试覆盖错设备、缺备份、坏hash、目标越界和覆盖NVS。

## 任务3：资源来源与CI

只读核查字体精确来源；若不能核实则选可追溯来源或保留明确未完成状态，不声称已验证。新增依赖说明、中文安装指南与校准导入说明。CI构建匹配版本/资源并打包boot文件和许可证，不带个人备份。先跑主机/脚本/安装工具单元测试，再K151构建、生成实际包并检查清单。

## 任务4：本台安装验收

用户确认底座USB/ON/无遮挡后才操作设备；读取并保存完整备份和校准，展示实际写入计划。完成源码复核后执行已授权的安装测试；校验写入且验证NVS未变。需要短按RST时由用户操作。先只读反馈，再本地两轴小幅探测、人工方向确认、验收启用；测试表情、摸头/松手恢复、点头摇头、跳舞RGB及结束关灯。若失败先恢复/排查，不发布可直接刷包。

## 任务5：发布

通过代码审查、自动测试、实机验证后提交推送，核对托管CI。发布v0.1.0-alpha.2测试包、中文指南、SHA256与许可；准确列出验证范围及长期通信可靠性限制，不夸大为全硬件通用。若需要用户物理操作或硬件未验收，保持该项待完成。
