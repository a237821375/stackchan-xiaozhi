# StackChan 内网音乐播放设计

日期：2026-10-01。状态：范围与接入方式已获用户同意，本文待用户审核。

## 目标与范围

用户在现有小智对话中点歌，机器人播放 Mac 的 Navidrome 音乐库。
这一轮实现播放、停止、切歌和唤醒打断；播放结束或失败后可继续对话。
保留现有表情、无字幕设置、头部命令、待机张望、摸头和猫呼噜声。
不实现音乐节拍动作、RGB 同步、播放列表、拖动进度、暂停续播或完整自建小智后端。

## 接入方式

采用机器人端 MP3 流式解码，复用已存在的 `espressif/esp_audio_codec` 依赖。
Mac 端继续提供经过认证的 Navidrome 音频和不含音乐库凭据的临时代理地址。
不增加 Mac 端专用 Opus 转换协议，也不更换整套机器人固件。

流程：

1. 用户说出歌曲名，小智调用 `resolve_music_url`。
2. 搜索工具返回歌曲信息，以及设备工具 `self.online_music.play_music` 的参数。
3. 设备工具验证参数，向主事件循环提交播放请求，立即返回“请求已接受”。
4. 主循环切换音频所有权；独立工作任务下载、解码和逐块投递 PCM。
5. 唯一的音频输出任务播放 PCM；完成、取消或错误事件回到主循环处理。

工具接受不等于已经播放成功。查询状态区分 preparing、playing、stopping、idle、error；
playing 以首个音乐 PCM 实际输出为准，结束以对应会话输出已排空为准。

## 设备工具契约

板卡启用音乐功能时注册：

- `self.online_music.play_music`：`play_type` 必须为 `url`，`url` 为音频代理地址；
  `url_song_name` 为展示与状态用标题；接受可选 `metadata_url`，首版不读取或显示歌词。
- `self.online_music.stop`：取消准备中或播放中的音乐；重复调用可安全返回已停止。
- `self.online_music.get_status`：返回状态、歌曲名和简短错误原因，不返回带令牌的 URL。

播放新歌曲即切歌：取消当前会话，再启动新会话。仅允许一个活动音乐会话。
工具描述明确说明搜索成功后继续调用设备播放工具，并说明停止需先唤醒。

## 音频与生命周期

新增独立 MusicPlayer，参考 NotifyPlayer 的工作任务与完成回调模式，不将音乐当通知处理。
Application 管理音频所有权，新增音乐状态，并通过现有状态机完成合法转换。
音乐能力由板卡配置启用；通用代码不依赖 StackChan 具体类或引脚。

AudioService 增加有界、可取消的外部 PCM 提交接口，复用当前播放队列和唯一输出任务。
输入 PCM 统一为扬声器输出采样率、16 位单声道；立体声下混和采样率转换在播放器任务完成。
网络与解码不得在主循环、舵机任务或音频输出任务执行。
沿用固定容量播放队列，不缓存整首歌；下载缓冲、MP3 帧缓冲和转换缓冲设置明确上限。

每次播放拥有递增的会话编号。取消后使旧编号失效，清理该会话待播数据。
缓冲不足期间音乐仍持有输出权，不能触发猫呼噜声，也不能被“队列暂时为空”误判为播放结束。
工作任务完成和音频队列排空分别记录；二者均满足才报告正常结束。
旧会话的回调、错误或延迟 PCM 不能更改新会话状态或重新发声。
停止不在主循环等待网络退出；工作任务在短超时或取消检查后自行释放资源。

## 对话、触摸和表情

收到播放请求后不同时播放云端 TTS 和音乐：准备期间等待当前短提示结束，随后占用输出。
提示等待设 3 秒上限，超过后取消当前提示并开始音乐；准备超时可取消音乐请求。
音乐期间保持唤醒检测，关闭普通对话语音上送，避免歌曲持续触发对话。
唤醒或手动进入对话先取消音乐，再走现有小智监听流程；不自动恢复被打断的歌曲。
正常结束或下载失败释放输出权并回到待机，不留下音乐状态或禁用的唤醒检测。

音乐使用现有普通表情，保持字幕隐藏，不把音乐 PCM 当成 AI 讲话触发摇头或嘴部讲话动画。
触摸仍可触发表情和头部动作，但音乐准备和播放期间抑制猫呼噜声；音乐结束后恢复原策略。
待机自动张望在音乐状态暂停；明确的 AI 头部指令接口保持原有能力。
本轮不修改舵机通信、动作幅度、速度或故障恢复实现。

## 网络输入与错误处理

首版只播放本机代理提供的 HTTP 地址：私有 IPv4、端口 8765、
路径 `/media/<token>/audio`；拒绝用户信息、片段、异常长度和其它 URL 形式。
不跟随重定向到其它地址，不把 URL 或 Token 写入日志。
连接和读取超时均设 2 秒；连续 5 秒无有效音频则终止并报告错误。
限制 ID3 元数据跳过大小为 256 KiB，限制解码帧、错误重试次数及缓冲增长。
支持首版已确认的 MP3 输入；不接受 HTML、无法解码的文件或不受支持的音频格式。
不做后台无限重连；用户可以重新点歌获取新的临时地址。
URL 过期、HTTP 错误、Wi-Fi 断开、格式错误均终止当前会话，清理资源并恢复对话能力。
错误状态用于查询，展示短提示；不能将网络失败描述成舵机或头部故障。

## 文件与变更边界

- 新增音乐播放器与可在主机验证的 URL/会话策略模块。
- `main/audio/audio_service.*`：有界 PCM 提交、音乐输出所有权、过期数据过滤。
- `main/application.*`、`main/device_state*`：音乐会话、唤醒取消、TTS 互斥和状态转换。
- StackChan 板卡集成与现有音频 codec：工具注册、猫呼噜声互斥、音乐表情事件。
- `main/CMakeLists.txt`、`main/Kconfig.projbuild`：按能力启用，保持其他板卡可构建。
- 不手工编辑生成输出、vendor、sdkconfig、分区、bootloader、NVS 或小智绑定。
