# StackChan：会回应摸摸头的小机器人

[![StackChan CI](https://github.com/a237821375/stackchan-xiaozhi/actions/workflows/stackchan.yml/badge.svg?branch=master)](https://github.com/a237821375/stackchan-xiaozhi/actions/workflows/stackchan.yml)

为 **M5Stack StackChan K151 / CoreS3** 开发的机器人固件，基于小智语音对话，加入黑底萌脸、摸头回应、语音控头、待机张望、跳舞灯效和实验性直接插话。

我们希望它聊天时有一点小动作，闲下来会看看周围，被摸头时会抬起脸回应，听到“跳舞”时能摇头晃脑。

**当前为实验测试项目，尚无稳定版。** `master` 已包含语音插话源码；已有 `0.1.0-alpha.2` Release 安装包不包含插话改动。请选择适合的[安装或开发入口](#开始使用)，首次安装需本机校准。

## 功能一览

| 功能 | 交互效果 |
| --- | --- |
| 黑底萌脸 | 21 种情绪、41 个 GIF 状态；讲话时切换当前情绪的动嘴版本，待机和困困闭嘴；隐藏对话字幕，保留顶部状态栏 |
| 摸头回应 | 喜欢表情、柔和抬头和轻点头；持续抚摸延续回应，松手约 3 秒恢复原姿态，新指令可取消恢复 |
| 待机张望 | 没有对话时每约 4～8 秒随机左右、上下看；进入对话停止张望 |
| 语音控头 | 回正、抬头、低头、左右看、两次点头或摇头、小幅调整、停止与恢复 |
| 讲话微动作 | 每轮最多两次轻微转头或点头；明确动作指令优先，困困不做微动作 |
| 跳舞与 RGB | 约 15 秒随机左右、上下摆头，12 颗 RGB 灯变色；结束恢复原姿态并关灯，摸头、新指令或故障可中断 |
| 直接语音插话（实验） | 讲话时直接开口打断，无需再次喊唤醒词；单台实测建议播放音量 60% |
| 运动保护与诊断 | 舵机反馈、限位、停滞和过载保护；区分通信超时与机械停滞 |

表情参考原厂几何风格重新绘制，动嘴跟随实际播放状态，不是音素级对口型。头部动作需通过本地校准和验收；语音指令还取决于模型正确调用工具，指令入队不等于已经到位。

## 开始使用

### 硬件适配

实测对象为 **StackChan K151、CoreS3 / ESP32-S3、16 MB Flash、8 MB Quad PSRAM、ILI9342C 显示配置**，使用原有底座、反馈舵机与头顶触摸传感器。其他显示屏修订版尚未验证。

### 选择源码或安装包

| 你的目标 | 从这里开始 |
| --- | --- |
| 不安装 ESP-IDF，试用已有实验固件 | [Releases](https://github.com/a237821375/stackchan-xiaozhi/releases) → [中文安装指南](docs/stackchan-install.md)。需要 Python 3.10+ 和 USB 数据线；已有 alpha.2 包不含直接插话 |
| 编译最新源码，试用直接插话或继续开发 | 从 `master` 获取源码，按[开发指南](docs/stackchan-development.md)编译并生成表情资源。最低 ESP-IDF 6.0.1；详见[插话说明](docs/stackchan-voice-interruption.md) |
| 首次启用头部动作或升级旧版本 | 按[校准指南](docs/stackchan-calibration.md)备份、配置本台零点并完成本地验收；缺失或损坏时头部保持禁用，旧验收标志不会自动沿用 |

源码独立板卡目录为 `m5stack/stackchan-k151`，构建变体为 `m5stack-stackchan-k151`。表情资源从公开字体、唤醒模型和仓库绘图代码生成，不需要个人设备备份。

### 试用直接插话

先说“把音量调到百分之六十”，再让它讲故事，播放中直接说下一句话。

单台实测 **60% 音量下可用，80% 时需要明显提高说话音量**。60% 是建议值，代码没有强制上限，也不会覆盖已保存音量。原理、测试条件和识别样例见[插话说明](docs/stackchan-voice-interruption.md)。

## 交互指令列表

以下按当前代码整理。引号内是口语示例，不是必须逐字匹配的固定关键词；需要 AI 正确调用设备工具，并以实际反馈判断是否执行成功。

### 头部动作与跳舞

| 可以这样说 | 对应交互 |
| --- | --- |
| “跳舞”“跳个舞”“扭一扭” | 开始约 15 秒随机左右、上下摆头，同时 RGB 灯切换颜色 |
| “停止跳舞”“别跳了” | 结束跳舞，恢复跳舞前姿态并关灯 |
| “回正”“看前面” | 回到校准后的正面姿态 |
| “抬头”“向上看” | 移到抬头预设位置 |
| “低头”“向下看” | 移到低头预设位置 |
| “向左看”“向左转头” | 向机器人自己的左侧转头 |
| “向右看”“向右转头” | 向机器人自己的右侧转头 |
| “再抬一点” | 相对当前基准姿态小幅抬头 |
| “再低一点” | 相对当前基准姿态小幅低头 |
| “再往左一点” | 相对当前基准姿态小幅左转 |
| “再往右一点” | 相对当前基准姿态小幅右转 |
| “点头”“点点头” | 两次点头，再回到基准姿态 |
| “摇头”“摇摇头” | 两次左右往返，再回到基准姿态 |
| “别动”“停止动作” | 停止运动并保持当前姿态，暂停待机张望和讲话微动作；正在跳舞时也会中断 |
| “恢复动作”“继续自动动作” | 满足验收和反馈条件时恢复自动动作；不是继续上一次舞蹈 |
| “头现在朝哪里？”“头部状态怎么样？” | 查询实际角度、目标姿态、是否跳舞和故障状态，不驱动头部 |

左右以机器人自身视角为准，正对它时与你的左右相反。相对调整由设备限制在安全范围内；边界处动作可能缩小或被拒绝。故障锁定时，应先检查连接、供电和活动空间，反馈有效后单次尝试恢复并查询状态，不能反复要求它强行动作。

### 设备基础控制

这些是当前固件保留的设备工具，部分取决于硬件初始化和服务支持，不能仅凭代码注册认为已完成实机验收。

| 可以这样说 | 对应交互与条件 |
| --- | --- |
| “音量调到 30%” | 设置扬声器音量，范围 0～100 |
| “把音量调到百分之六十” | 直接插话的实测建议播放音量；不保证所有设备或环境均适用 |
| “声音大一点”“声音小一点” | 查询当前音量后调整；具体调整量由 AI 选择 |
| “屏幕亮度调到 50%”“屏幕暗一点” | 设置屏幕背光亮度，范围 0～100；不是 RGB 灯亮度 |
| “现在电量多少？”“现在音量多少？”“设备状态怎么样？” | 查询设备实际返回的电池、音量、屏幕、网络等状态 |
| “切换深色主题”“切换浅色主题” | 显示主题可用时切换系统界面主题；不代表重新绘制 GIF 或改变萌脸黑底 |
| “看看你面前是什么” | 摄像头初始化成功、对应工具可用且服务支持时拍照分析；需实机验证 |

### 触摸与自动交互

| 操作或场景 | 对应交互 |
| --- | --- |
| 轻触头顶并持续摸摸 | 喜欢表情、柔和抬头，再轻微上下点头；需自动动作已启用且反馈有效 |
| 松开头顶约 3 秒 | 恢复触碰前姿态；新的头部指令可以取消恢复 |
| 跳舞时摸头 | 中断跳舞与灯效，满足条件时进入摸头回应 |
| 正常运行时短触屏幕后松开（少于 500 ms） | 根据当前状态开始、结束或中断对话；不是头顶触摸 |
| 待机，没有明确指令 | 每约 4～8 秒自动张望，进入对话停止张望 |
| 机器人正在讲话 | 当前情绪的嘴巴动画与少量讲话微动作；困困不动嘴、没有讲话微动作 |

## 已知问题与未实现功能

- **插话识别仍有错误**：短词“停”和长句开头可能识别不准；丢弃停播前音频、只识别后半句尚未实现。
- **自动重启尚未修复**：AXP2101 电池状态读取超时会触发程序中止并重启；AEC 处理期间也出现过 CPU 看门狗告警。两者是否关联尚未确认，详见[插话问题记录](docs/stackchan-voice-interruption.md#已知稳定性问题)。
- **舵机偶发串口错码根因未确定**：短期正常不能保证长期稳定，详见[板卡说明与诊断记录](main/boards/m5stack/stackchan-k151/README.md)。
- 全部交互组合、首次安装全流程、断网重连、其他机器和长期运行仍需按[实机验收清单](docs/stackchan-hardware-validation.md)验证。
- 猫咪呼噜声、音乐播放、随音乐节拍跳舞，以及独立 RGB 语音控制尚未实现。未完成的呼噜运行代码、录音和专用测试已移除，摸头表情和动作保留。
